# Security

## Reporting

Before a public hosting location exists, report a vulnerability privately to the repository
owner. After publication, use the hosting platform's private vulnerability-reporting feature.
Do not include Session IDs, snapshot files, terminal contents, Hook payloads, or credentials in
a public issue.

## Scope

Security reports should identify the affected version or commit and a minimal reproduction.
Relevant boundaries include Hook JSON validation, OSC transport, Unix-socket peer validation,
managed configuration updates, private snapshot storage, and retention.

General support and feature requests can use the public issue tracker after publication.
